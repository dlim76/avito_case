# Avito Antibot Classification

## Задача

Нужно для каждой `cookie_id` предсказать `score ∈ [0, 1]` — вероятность того, что трафик относится к автоматизированному сбору данных.

Основная метрика:

`Precision при Recall >= 0.70`

Финальный результат на скрытом тесте:

- **Precision@Recall>=0.70 = 0.67360**
- константный baseline = **0.09391**

---

## Подход

### Обработка событий

Для каждой cookie использовались только события внутри разрешённого окна:

```text
window_start_ts <= event_ts < window_end_ts
```

Это предотвращает leakage: события после окончания окна не использовались при построении признаков.

Пропуски не удалялись автоматически, так как многие из них естественно зависят от типа события. Например, `search_query` заполнен только для поисковых событий, а координаты курсора присутствуют не для всех событий.

Полные дубликаты событий также не удалялись: их наличие оказалось потенциально полезным сигналом автоматизированного поведения. На их основе были построены отдельные признаки.

Сырые категориальные значения напрямую в финальную модель не передавались — использовались агрегаты по ним.

---

## Признаки

Финальная модель использует набор `basic + temporal + pointer`.

### Basic features

Для каждой `cookie_id` рассчитывались:

- количество событий;
- количество уникальных типов событий;
- количество уникальных объявлений;
- количество категорий, локаций и типов продавцов;
- количество поисковых запросов и страниц поиска;
- количество платформ и User-Agent;
- количество каждого типа события;
- возраст cookie;
- количество и доля дублирующихся событий.

### Temporal features

По последовательности событий рассчитывались:

- длительность активности;
- число уникальных timestamps;
- mean / median / std / min / max интервалов между событиями;
- 25% и 75% квантили интервалов;
- доля очень быстрых переходов;
- интенсивность событий.

Идея: автоматизированное поведение может отличаться от человеческого скоростью и регулярностью действий.

### Pointer features

По `pointer_x` и `pointer_y` рассчитывались:

- количество событий с координатами;
- количество уникальных координат;
- доля событий с координатами;
- число уникальных пар `(x, y)`;
- повторяемость координат;
- расстояния между последовательными положениями курсора;
- статистики этих расстояний.

Pointer-признаки дали заметный прирост основной метрики.

---

## Валидация

Случайный `train_test_split` не использовался, так как `test` расположен позже `train` по времени.

Использовалась temporal validation:

```text
Fold 1: train < 2026-04-13, valid 2026-04-13 ... 2026-04-14
Fold 2: train < 2026-04-15, valid 2026-04-15 ... 2026-04-16
Fold 3: train < 2026-04-17, valid 2026-04-17 ... 2026-04-19
```

На каждом фолде модель обучалась только на более ранних данных.

---

## Эксперименты

В качестве baseline использовалась Logistic Regression.

| Features | P@R>=0.70 |
|---|---:|
| basic | 0.2605 |
| basic + temporal | 0.3237 |
| basic + temporal + pointer | 0.4746 |

Также были протестированы:

- Random Forest;
- CatBoost;
- LightGBM;
- дополнительные User-Agent / platform features;
- diversity / repetition features;
- blend LightGBM + CatBoost.

Дополнительные группы признаков не дали стабильного улучшения основной метрики и не вошли в финальное решение.

---

## Финальная модель

Лучший результат показал LightGBM.

Гиперпараметры подбирались с помощью Optuna по средней `Precision@Recall>=0.70` на temporal CV.

Для зафиксированной конфигурации LightGBM:

| Fold | P@R>=0.70 |
|---|---:|
| Fold 1 | 0.7436 |
| Fold 2 | 0.6769 |
| Fold 3 | 0.7134 |

Среднее значение:

**Mean P@R>=0.70 = 0.7113**

Финальные параметры:

```python
{
    'n_estimators': 595,
    'learning_rate': 0.038955684888820244,
    'num_leaves': 60,
    'max_depth': 4,
    'min_child_samples': 26,
    'subsample': 0.8595208313732137,
    'colsample_bytree': 0.8686494619589004,
    'reg_alpha': 9.366233563863002,
    'reg_lambda': 9.695591790095328,
    'random_state': 42
}
```

Также проверялся blend LightGBM + CatBoost. На основных CV-фолдах он давал небольшой прирост, но на отдельном temporal holdout чистый LightGBM оказался лучше:

```text
LightGBM: 0.6242
Blend:    0.6095
```

Поэтому для финального submission использовался LightGBM.

После выбора модели она обучалась на всём `train`.

## Воспроизводимость

Используется фиксированный seed:

```python
RANDOM_STATE = 42
```

Финальные параметры LightGBM зафиксированы в notebook, поэтому повторный запуск Optuna для получения `submission.csv` не требуется.

Для запуска:

```bash
pip install -r requirements.txt
```

Данные должны лежать в:

```text
data/
├── train.csv
├── test.csv
├── events.csv.gz
└── sample_submission.csv
```

После этого открыть `main.ipynb` и выполнить:

```text
Restart Kernel -> Run All
```

В результате в корне проекта создаётся:

```text
submission.csv
```

с колонками:

```text
cookie_id
score
```
